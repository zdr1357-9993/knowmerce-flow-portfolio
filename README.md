# KNOWMERCE Flow

입출고·재고·승인·일정·주문서 가공을 연결한 물류 서비스 프로토타입입니다.
이 저장소는 채용 검토용 물류 업무 시스템 프로토타입의 소스입니다.
공개 홈은 로그인 없이 브라우저별 예시 데이터로 체험할 수 있습니다.
기존 인증 API와 계정 데이터는 로그인 보호를 유지하며 공개 체험에서는 사용하지 않습니다.

**[브라우저 체험](https://knowmerce-flow.knowmerce-demo.workers.dev/)** · **[구조·설계 선택·검증 범위](docs/ARCHITECTURE.md)**

## 빠르게 살펴보기

- **업무 설계**: 공통 품번·입출고 요청·승인·변경 이력으로 부서 간 정보 기준을 연결합니다.
- **구현**: React 19·TypeScript, vinext/Vite, Cloudflare Workers·D1·Drizzle, Tailwind CSS를 사용합니다.
- **검증**: 권한·동시 수정·재고·주문서 수량 대조를 코드로 확인합니다. AI 생성 결과도 동일한 기준으로 확인합니다.
- **현재 범위**: 개인 시제품이며, 사내 대규모 ERP 운영·전사 도입 완료를 의미하지 않습니다.

최근 리팩토링에서는 화면 공통 요소, 요청 입력 검증, HTTP 명령 처리, D1 저장을 분리했습니다.
압축된 작성 코드를 포맷터로 정리하고 자동 검사 실행 방법을 통일했습니다.

## 현재 포함 기능
- 요청자·물류 담당자·어드민 권한, 관리자의 계정 발급·비밀번호 초기화
- 상품 일괄 발번, 품번 조회, 재고 null/0 구분, 재고 변경 이력
- 다중 상품 입출고 저장·바로 요청·승인·수정 요청·취소·완료
- 슬랙 논의 중·이슈 해결 중 등 대시보드 상태 필터
- 다보내·패박 전사 캘린더, 기간과 출고 완료 예상 시점
- 반복 당첨 차감·당첨 앨범 추가·버전 배분·박스 분할 예시
- MD 포장 용량과 청구무게 설정, 물류사별 비용 비교
- 국내·해외 XLSX 다운로드와 수량 대조
- 3PL 계약·운임 기준 및 상시판매 준비 작업

## 구현 범위
Cloudflare Worker + D1 기반입니다. 업무 데이터는 JSON 워크스페이스 단위로 저장하며,
기획서의 정규화 논리 ERD가 그대로 실행 DB로 구현된 것은 아닙니다.
Slack 실제 전송·외부 WMS 제출·실시간 RF 모델 추론은 연결하지 않았습니다.
주문 업로드는 CSV이며 결과 다운로드는 XLSX입니다. FS/SS 전용 전체 규칙은 별도 범위입니다.

## 개발·확인
Node 22.13 이상. 의존성 버전은 package.json과 pnpm-lock.yaml을 참고합니다.

```sh
pnpm install
pnpm test
pnpm typecheck
pnpm build
pnpm dev
```

로컬 실행·D1 마이그레이션·인증 구성은 LOCAL_DEVELOPMENT.md를 참고하세요.
계정 통합 검사는 로컬 서버에서 TEST_ADMIN_LOGIN·TEST_ADMIN_PASSWORD를 환경변수로 전달합니다.
실제 인증 값은 .dev.vars/.env.local에만 두며 GitHub에는 포함하지 않습니다.

## 배포
기존 공개 시연 URL: https://knowmerce-flow.knowmerce-demo.workers.dev/
Cloudflare 배포는 환경별 D1과 비밀값을 설정한 뒤 별도로 진행합니다.
wrangler.jsonc의 DB ID는 공개용 자리표시자입니다. 본인 계정의 리소스로 바꾼 뒤 배포합니다.
GitHub 자동 검사는 배포하지 않습니다. 배포는 별도 승인과 환경 구성이 필요합니다.

## 문서
- LOCAL_DEVELOPMENT.md: 최신 로컬 구현 상태
- lib/: 업무·자동화 규칙
- app/: 화면과 API
- drizzle/: 실제 실행 DB 마이그레이션
- tests/: 업무 규칙과 로컬 인증 검사

## 공개본 구성
기존 비공개 저장소의 커밋 이력, 배포 상태 파일, 로컬 설정과 DB는 포함하지 않습니다. 예시 데이터만 포함합니다.
